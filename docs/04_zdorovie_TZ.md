# ТЗ. Кейс №4: трекер здоровья

Основа: [заказ FL.ru №5309362](https://www.fl.ru/projects/5309362/kursovaya-razrabotka-veb-prilojeniya-treker-zdorovya-i-analiz-pokazateley-na-django-python.html), 01.05.2024, бюджет 18 000 ₽, 6 откликов, исполнитель выбран. Учебный кейс, заказчику ничего не отправляем.

Рабочее название продукта: **«Тонус»**.

В заголовке заказа стоит «Курсовая»: это учебная работа заказчика, и он просит Django (Python). Кейс собираем на общем ядре трекеров (Node.js), как и остальные четыре. Для настоящего заказчика пришлось бы писать на Django, это первый вопрос к нему. Что сказано в заказе, а что предложено исполнителем, отмечено ниже.

## 1. Цель

Человек ведёт показатели здоровья в одном месте, видит, как они меняются, и получает понятные подсказки по анализам. Врач, нутрициолог и тренер работают с запросами своих клиентов и видят только то, что клиент им открыл.

## 2. Роли и права

Роли человек, врач, тренер, нутрициолог взяты из заказа. Администратор и правило доступа специалистов предложены.

| Действие | Клиент | Врач | Нутрициолог | Тренер | Администратор |
|---|---|---|---|---|---|
| Бесплатные материалы и статьи | да | да | да | да | да |
| Вести свои показатели, цели, напоминания | да | нет | нет | нет | нет |
| Вносить анализы и получать подсказки | да | нет | нет | нет | нет |
| Отправлять запрос специалисту | да | нет | нет | нет | нет |
| Видеть показатели и анализы клиента | свои | по запросу клиента | по запросу клиента | только показатели активности | нет |
| Отвечать на запрос | нет | заключение | меню | запись | нет |
| Вести расписание тренировок | нет | нет | нет | да | нет |
| Публиковать статьи | нет | да | да | да | да |
| Управлять пользователями и бесплатными материалами | нет | нет | нет | нет | да |

**Предложено:** специалист видит данные клиента только после его запроса. Клиент может закрыть доступ, после этого данные специалисту не видны, а его прошлые ответы остаются у клиента. Права проверяет сервер.

## 3. Бесплатные материалы

Из заказа: без регистрации на сайте можно получить пробное меню, пробные уроки по питанию и тренировкам.

- Пробное меню на 3 дня: приёмы пищи, состав, калории.
- 3 пробных урока по питанию и 3 по тренировкам: текст и картинки.
- Статьи о здоровом образе жизни, питании, активности, сне. Разделы и поиск по заголовку.
- Видео не храним: если у урока есть видео, это ссылка на внешний сервис.

## 4. Дневник показателей

Из заказа: вес, рост, обхват талии, давление, пульс, физическая активность, уровень стресса, качество сна.

| Показатель | Как вносится |
|---|---|
| Вес, обхват талии | кг, см |
| Рост | см, в профиле, меняется редко |
| Давление | верхнее и нижнее |
| Пульс | уд/мин в покое |
| Активность | шаги или минуты тренировки |
| Стресс | шкала 1–10 |
| Сон | часы и качество 1–5 |

- Вносить можно не всё сразу, одна запись на показатель в день, её можно поправить.
- Индекс массы тела считается сам из веса и роста.
- Быстрый ввод на экране «Сегодня», не дольше минуты.
- Сервер отклоняет невозможные значения (вес 0, давление 400).

## 5. Графики и сравнение

Из заказа: показатели в виде графиков и диаграмм, сравнение с предыдущими данными для выявления тенденций.

- График по каждому показателю за 7 дней, 30 дней, 3 месяца. Давление двумя линиями, сон столбцами.
- Сравнение: последнее значение, среднее за выбранный период и за такой же период до него, стрелка тенденции.
- Если для показателя задана цель, она видна на графике линией.
- Графики рисуем сами, без внешних библиотек и без отправки данных сторонним сервисам.

## 6. Анализы и подсказки

Из заказа: загрузить свой анализ и получить рекомендации по 3 показателям, отвечает не врач, а программа по определённым цифрам.

- Клиент вносит значения трёх показателей из анализа и дату сдачи. В демо: глюкоза натощак, общий холестерин, гемоглобин. Список и пороги утверждает заказчик.
- Программа сравнивает каждое значение с диапазонами и показывает заранее написанный ответ: «в пределах нормы», «ниже», «выше», что можно сделать и к какому врачу обратиться. Для гемоглобина диапазон зависит от пола.
- Под каждым ответом пометка: это не диагноз и не замена консультации врача.
- **Предложено:** к анализу можно приложить файл (PDF или фото), его видит врач по запросу. Файл программа не читает, цифры вносит человек. Распознавание бланка — допродажа.
- История анализов: значения по датам, рост или снижение по сравнению с прошлым разом.

## 7. Цели и уведомления

Из заказа: уведомления о достижении целей здоровья или изменении показателей.

- Цели: вес к дате, шаги в день, часы сна. Прогресс виден на «Сегодня» и на графике.
- Уведомление один раз, когда цель достигнута.
- **Предложено:** уведомление о заметном изменении: давление выше 140/90 два дня подряд, вес изменился больше чем на 3 кг за неделю. Пороги задаёт заказчик.

## 8. Напоминания

Из заказа: напоминания о заполнении данных, приёме лекарств, тренировках и других событиях. Бот к сайту в заказе упомянут как пример.

- Лекарство: название, доза, время, дни недели. Клиент отмечает «принял», после отметки напоминание не повторяется.
- Заполнить дневник: в выбранное время, только если сегодня ничего не внесено.
- Тренировка: за час до записи к тренеру.
- Каналы в MVP: колокольчик в приложении и push в браузере, готовое решение из кейса №2. Telegram-бот — допродажа, основа есть в кейсе №1.

## 9. Запросы специалистам

Из заказа: нутрициолог и врач видят запросы на составление меню, просмотр анализов; тренер ведёт запись на свои тренировки.

- **Нутрициологу:** «составить меню». Клиент указывает цель, ограничения, аллергии. Нутрициолог видит показатели клиента и отвечает меню по дням.
- **Врачу:** «посмотреть анализы». Врач видит анализы, файлы и показатели, пишет заключение.
- **Тренеру:** запись на тренировку из его расписания. Слот: дата, время, вид, число мест. Нельзя записаться в полный слот или дважды. Клиент и тренер могут отменить запись.
- Статусы запроса: Новый, В работе, Готово, Отклонён. Ответ специалиста приходит клиенту уведомлением.

## 10. Экраны

**Без входа:**
1. **Главная.** Что даёт сервис, бесплатные материалы, вход.
2. **Пробное меню, уроки, статьи.**

**Клиент:**
3. **Сегодня.** Быстрый ввод, напоминания на сегодня, прогресс целей.
4. **Показатели.** Графики и сравнение.
5. **Анализы.** Ввод, подсказки, история.
6. **Специалисты.** Запросы, ответы, запись к тренеру, открытые доступы.
7. **Цели и напоминания.**

**Специалисты и администратор:**

8. **Запросы.** Очередь, главный экран врача и нутрициолога.
9. **Карточка клиента.** Только то, что клиент открыл.
10. **Расписание.** Главный экран тренера.
11. **Статьи.** Редактор для специалистов и администратора.
12. **Пользователи и материалы.** Администратор.

Каждая роль сразу попадает на свой экран: клиент на «Сегодня», врач и нутрициолог на запросы, тренер на расписание.

## 11. Оформление

Спокойная медицинская гамма, отличается от первых трёх кейсов: свежий зелёно-бирюзовый на светлом, мягкие карточки, крупные цифры показателей. Сначала телефон, светлая и тёмная темы.

## 12. Вход и безопасность

- Логин и пароль, роли, приглашения для специалистов, защита от подбора. Основа из кейса №1.
- Данные о здоровье по закону о персональных данных — особая категория. Для заказчика: сервер в России, отдельное согласие на обработку при регистрации и отдельное согласие при открытии доступа специалисту. Это записать в инструкцию передачи.
- Файлы анализов отдаются только после входа и только тем, кому клиент открыл доступ.

## 13. Демо для портфолио

- Адрес: `tonus.myfreelab.ru`.
- Выдуманные клиенты и специалисты, показатели за 3 месяца, вход в один клик за каждую роль, сброс раз в сутки.
- На каждом экране ввода предупреждение: в демо не вводите настоящие данные о здоровье.
- Загрузка файлов анализов в демо выключена: сервер демо за рубежом, медицинские документы посетителей туда отправлять нельзя. Показан пример приложенного файла.

## 14. Этапы

1. Роли, вход, бесплатные материалы, статьи.
2. Дневник показателей, графики, сравнение, цели.
3. Анализы и подсказки.
4. Запросы специалистам, доступ, расписание тренера.
5. Напоминания и уведомления, оформление, публикация.

## 15. Критерии готовности MVP

- Специалист не открывает данные клиента без его запроса и после закрытия доступа, даже по прямой ссылке. Тренер не видит анализы.
- Клиент не видит чужие данные.
- Подсказки по анализам верны на каждой границе диапазона, с учётом пола для гемоглобина.
- Графики совпадают с внесёнными данными, сравнение периодов и индекс массы тела считаются верно.
- Невозможные значения показателей отклоняются сервером.
- Напоминание о лекарстве приходит в своё время один раз и не приходит после отметки.
- Уведомление о цели приходит один раз.
- В полный слот тренера записаться нельзя, дважды в один слот тоже.
- Бесплатные материалы и статьи открываются без входа.
- Все экраны работают на телефоне шириной 360 пикселей.

## 16. Не входит в MVP

Платные разделы и оплата, видеокурс и хранение видео, распознавание бланков анализов, Telegram-бот, видеоконсультации, данные с часов и фитнес-браслетов, приложения в магазинах. Это допродажи.

Код, развёртывание на сервере, краткая инструкция. Для курсовой дополнительно описание архитектуры и схема базы.
